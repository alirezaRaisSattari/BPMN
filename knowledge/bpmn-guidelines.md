# اصول مدل‌سازی BPMN 2.0

هر فرآیند باید دقیقاً یک رویداد شروع (Start Event) داشته باشد مگر آنکه چند محرک مستقل وجود داشته باشد.

هر مسیر در فرآیند باید به یک رویداد پایان (End Event) ختم شود؛ هیچ فعالیت یا گیت‌وی نباید بدون جریان خروجی «معلق» بماند.

فعالیت‌هایی که توسط انسان انجام می‌شوند از نوع User Task و فعالیت‌های خودکار سیستم از نوع Service Task هستند. فعالیت سیستمی را هرگز به یک نقش انسانی نسبت ندهید.

از Exclusive Gateway (XOR) برای تصمیم‌های مبتنی بر شرط استفاده کنید؛ هر مسیر خروجی باید یک شرط مشخص و متقابلاً انحصاری داشته باشد و یک مسیر پیش‌فرض تعریف شود.

از Parallel Gateway (AND) برای فعالیت‌هایی که هم‌زمان و بدون وابستگی اجرا می‌شوند استفاده کنید؛ یک Parallel Gateway که مسیرها را باز می‌کند باید با یک Parallel Gateway که آن‌ها را می‌بندد (join) متوازن شود.

هر گیت‌وی تصمیم که مسیرها را باز می‌کند بهتر است در صورت نیاز با یک گیت‌وی merge بسته شود تا ساختار بلوکی و معتبر بماند.

نام‌گذاری فعالیت‌ها باید به‌صورت «فعل + مفعول» باشد (مثل «ثبت سفارش»، «تأیید درخواست»). نام رویدادها وضعیت را توصیف می‌کند (مثل «سفارش دریافت شد»).

نقش‌ها به‌صورت Lane در یک Pool مدل می‌شوند؛ هر فعالیت باید به یک Lane (نقش مسئول) تعلق داشته باشد.

اشیای داده (Data Object) ورودی و خروجی فعالیت‌ها را نشان می‌دهند و برای ردیابی وضعیت درخواست مفیدند.
